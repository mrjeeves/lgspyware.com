01 · The mechanism

What one cable does

Recovered from a machine we own and have not cleaned, so the chain can be checked against ours.

  1. T+0You connect itOne cable — the only deliberate action in the chain.
  2. T+0Windows Update deliversTwo LG packages signed as drivers, carrying no driver code. One invents a phantom device so the other can bind to it.
  3. T+32sSYSTEM installs the appNo window, no EULA, no Programs and Features entry.
  4. T+9moStill maintainedMonitor unplugged Oct 2025; Windows still updating the app as SYSTEM in Jul 2026.

Removing the app is not enough: both packages stay in the driver store, wired to 51 hardware IDs, and re-arm on the next listed panel. Both layers are in the fix. Full chain and INF directives: the forensics.

02 · The check

Am I affected?

Three checks, no monitor required. If an affected LG panel has ever touched this PC — months ago, long gone — run them.

Check 1 · 10 seconds Installed apps

Settings → Apps → Installed apps. Search LG Monitor, then McAfee.

Either one you didn't install → hit
Check 2 · the damning one Install history

Win+R → perfmon /rel. Look for LGElectronics.LGMonitorApp.

Logged as “Successful Windows Update,” not an app install
Check 3 · for techs Driver store

pnputil /enum-drivers → look for LG Electronics .inf entries.

Present → armed, even if the app is gone
Any one of the three = affected. “I unplugged it” is not “it's clean” — the software stays behind, and so does the trigger.

03 · Removal

The fix

Two layers, both required. Remove the app and the machine still re-arms; remove the packages too and it stops.

Layer 1
The app

Settings → Apps → Installed apps → uninstall LG Monitor App. Or elevated PowerShell:

Get-AppxPackage -AllUsers LGElectronics.LGMonitorApp | Remove-AppxPackage -AllUsers
Layer 2
Both delivery packages

Elevated prompt. Find the two LG Electronics Inc. entries, then delete each by its oemXX.inf name:

pnputil /enum-drivers
pnputil /delete-driver oemXX.inf /uninstall

Surgical: every other device keeps its drivers and companion software, and real driver updates keep flowing. Windows Home, no Group Policy? There's a registry method — and four caveats worth reading first, including that we have not reproduced a blocked install with it. The Home method, with caveats →

04 · Hardening

Windows Home: the registry method

There is one hardening step beyond removal. It comes with four caveats, and they matter more than the command.

This is the registry value behind the Group Policy “Prevent automatic download of applications associated with device metadata” (older ADMX files name the same setting “Prevent device metadata retrieval from the Internet”). Elevated prompt, then reboot:

reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\Device Metadata" /v PreventDeviceMetadataFromNetwork /t REG_DWORD /d 1 /f

Reverse it with reg delete on the same value. UI equivalent, any edition: Settings → System → About → Advanced system settings → Hardware → Device Installation Settings → No.

Read this before you rely on it
  • It blocks one path. Microsoft documents it against apps tied to device metadata, never as gating driver delivery. The documented chain rode the driver channel.
  • Home isn't in the docs. Pro, Enterprise, Education and IoT Enterprise only. Setting it on Home is harmless; claiming Microsoft supports it there isn't.
  • It's deprecated, replaced by Driver Package Container Metadata.
  • The cost: companion software for every vendor stops arriving automatically, printers included. Real drivers keep flowing.
  • Field evidence against it: a March 2026 user watched the install land with the equivalent policy enabled — and we have not reproduced a blocked install with it.

On Pro/Enterprise: same setting at gpedit.msc → Computer Configuration → Administrative Templates → System → Device Installation. Community testing says it stops these installs on many machines; same caveats apply. Package removal remains the primary fix — the only step verified here.

02 · The reach

Why so many machines qualified

Microsoft documents three preconditions for this delivery. All three are the default path through a consumer install, which is how an install base was built for twenty months without anyone choosing it:

  • You accepted “Recommended Settings” at Windows setup
  • You're signed in to the Microsoft Store
  • You're online

Declining Recommended Settings is a real reason you may have been spared. Both LG packages are signed “Microsoft Windows Hardware Compatibility Publisher” — Microsoft co-signed the distribution — on a machine at stock defaults.

Microsoft's own developer documentation: “the automatic installation feature does not provide a notification to the user when the app is installed.”
05 · The answer

What LG says. What the machine shows.

LG emailed outlets on July 22 rather than publishing. Its paragraph runs in full across these rows, strongest denial included.

LG says

“LG Electronics reiterates that McAfee is not installed automatically and is never installed without the user's explicit consent… Under no circumstances is McAfee installed automatically or without user authorization.”

What we found

Agreed — and nobody said otherwise. McAfee was never what installed silently. LG's own app was. McAfee is what that app then put on screen, on 31 of 32 consecutive boots.

LG says

“The LG Monitor App Installer is distributed through Microsoft's official Windows distribution process, which included McAfee as an option.”

What we found

Correct, and that is the finding. “Official” describes the road. It does not describe consent.

LG says

The Monitor App Installer “does not access, collect, or transmit any customer personal data.”

What we found

Open. We captured no network traffic and have never claimed exfiltration — our findings are consent and persistence. One packet capture settles it either way. Send one.

For contrast: Dell told TechSpot that current Alienware Command Center versions require the user to approve installation and carry no third-party ads, with an opt-in prompt added in AWCC 6.6, February 2025. Windows can still start that install after detecting the hardware. Same road, consent step bolted on.

06 · The promise

The concession LG published where nobody was looking

Twelve days after the McAfee climbdown, on a regional support page, LG addressed the install itself for the first time.

“Following customer feedback, LG removed the recommendation and does not plan to recommend McAfee or other third-party software through the Installer in future.”

“As part of its commitment to continuously improving the customer experience, LG is updating the Installer so customers can decide whether they would like to install it.”

LG, “LG Monitor App Installer,” August 3, 2026

“It” is the Installer — the app that arrives on its own. That is LG conceding the consent gap, and it goes further than the July agreement, which only covered the advertisement.

Status todayNot shipped. The app's Store product has not been updated since August 12, checked again on September 12. No build, no version, no date.
Where it ranOne regional support site. We found no coverage of it in any outlet, then or since.
What it omitsThe two resident .inf packages, and every machine already carrying the app.
One line that doesn't holdThe notice says applications “are only installed if the customer chooses to proceed.” True of the apps the Installer offers; not true of the Installer, which arrived under SYSTEM with nothing to proceed through.

07 · The timing

Two years quiet, then the advertising arrived

The install base was built long before the ads were. Microsoft's Tech Community thread opens November 18, 2024, and for twenty months every post is about the mystery install — a repair tech in July 2025 calling it a force-installed PUP on client machines; a March 2026 user watching it land with the device-metadata and Store-disable policies both enabled. Not one post mentions advertising, and the reply marked as the solution said the app was safe.

Then July 1, 2026: the first McAfee Scam Detector pop-up. Every reply since is about ads. That date fits the app's own version chain on our machine:

1.2405.3001.0installed Sep 30, 2025 1.2602.502.0interim build 1.2606.1601.0SYSTEM self-update, Jul 9, 2026

The numbering reads as year-month. A June 2026 build rolling out through staggered Store updates lands exactly where the thread turns into ad complaints and Gamers Nexus's three-year-old UltraFine starts popping mid-production. On July 21, Windows Latest found the Store listing carrying an “Additional App – McAfee” changelog entry with 30-day-trial copy: a changelog ships inside a build, not as a server-side flip. Those references are gone from the listing now.

Still unproven: whether the advertising is only in the build, or can also be switched on remotely. The app is internet-connected and its payload can change.

08 · The permissions

What a monitor app asks for

Reading the Store listing and LG's terms on air, Gamers Nexus found the auto-installed app “technically” holds permission to use all system resources, plus:

System resources Internet connectivity Location Device data Contacts Credentials Transactions Online activity

It's a monitor. It should not want your logins, location, contacts or transactions.

The limits of our evidence
  • A permission is not a transmission. This list is GN's reading of the listing and LG's terms — with GN's own “technically” hedge — not something anyone watched happen.
  • We captured no network traffic. LG says the installer “does not access, collect, or transmit any customer personal data.” That stands unrefuted here.
  • One packet capture closes the gap in either direction. Send us one.
